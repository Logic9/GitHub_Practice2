# DOS Time Analyzer

8자리 16진수로 표현한 DOS/FAT 날짜·시간 값을 사람이 읽을 수 있는 연·월·일·시·분·초로 해석하는 C 학습 코드입니다. 바이트 순서 변환과 비트 마스크를 이용한 날짜 필드 추출을 함께 실습합니다.

## 코드 구성

현재 소스 파일은 `DOSTIME_Analyzer.c` 한 개입니다.

| 함수 | 역할 |
| --- | --- |
| `main()` | 입력 길이 검사, 호스트 엔디언 확인, 변환·출력 흐름 |
| `input_string()` | 콘솔 입력 읽기 |
| `extract_hex()` | 16진 문자 검사와 32비트 값 조합 |
| `isLittleEndian()` | 실행 환경의 바이트 순서 확인 |
| `LittleEndian_to_BigEndian()` | 4바이트 순서 뒤집기 |
| `dos2unixtime()` | DOS 비트 필드를 달력 날짜·시간으로 나눠 출력 |
| `unix2dostime()` | 달력 필드를 DOS 날짜·시간 비트에 조합 |

함수 이름에 `unix`가 있지만 Unix epoch 초를 반환하는 구현은 아닙니다. 출력에는 입력값을 다시 조합한 값과 코드에 고정된 예시 날짜의 DOS 값도 포함됩니다. 시간대 변환이나 파일 메타데이터 읽기는 하지 않습니다.

## 현재 상태: 수정 전 실습 원본

현재 코드는 현대 C 컴파일러에서 바로 빌드·실행할 수 있는 상태로 검증되지 않았습니다.

- Clang 문법 검사에서 `input_string()`의 사전 선언 누락 오류가 발생합니다.
- 입력 함수가 `realloc()`으로 확보한 버퍼를 초기화하지 않은 채 `strcat()` 대상으로 사용하고, 반환 버퍼도 사용하지 않아 메모리 처리 수정이 필요합니다.
- 입력 오류, 할당 실패, 날짜 범위와 윤년을 충분히 검증하지 않습니다.
- `int`의 크기와 부호 있는 비트 연산에 의존합니다. 명시적인 `uint32_t` 사용과 경계 조건 검토가 필요합니다.
- 호스트 엔디언에 따른 바이트 뒤집기가 입력 규약과 일치하는지 테스트가 필요합니다.

기록 보존을 위해 소스의 동작을 임의로 바꾸지 않았습니다. 위 문제를 수정하고 알려진 날짜와 잘못된 입력 사례를 확인한 후 실행해야 합니다.

## 개발 환경과 확인 명령

별도 외부 라이브러리나 환경 변수는 없습니다. C 컴파일러로 다음과 같이 현재 상태를 점검할 수 있습니다.

```sh
cc -Wall -Wextra -fsyntax-only DOSTIME_Analyzer.c
```

문제 수정 후 일반적인 빌드 형식은 `cc -Wall -Wextra DOSTIME_Analyzer.c -o dostime-analyzer`입니다. 이 문서는 실행 성공을 보장하지 않습니다.
